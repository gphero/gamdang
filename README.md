# 감당할수있겠나!

큰 지출을 감당할 수 있는지 미리 굴려보는 가계 현금흐름 예측 시스템.

시작 잔고에서 출발해 수입·지출을 월 단위로 굴리고, 큰 지출을 일시불·할부·대출 중
어떤 구조로 치르느냐에 따라 월말 잔고가 어떻게 달라지는지 시나리오별로 비교합니다.

## 실행

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:5173 이 열립니다.

```bash
npm run build     # dist/ 에 정적 파일 생성
npm run preview   # 빌드 결과 확인
```

## 화면

| 탭 | 하는 일 |
|---|---|
| 대시보드 | 월말 잔고 스트립, 시나리오별 잔고 추이 차트, 월별 상세 표 |
| 수입·지출 | 반복/일회성 항목. 주기와 연 증가율 지정 |
| 큰 지출 | 차·이사·수술 같은 목돈. 일시불 / 할부 / 대출과 상환 조건 |
| 시나리오 | 같은 지출을 다른 구조로 놓고 비교 |
| 상품 카탈로그 | 기관·할부·대출 상품 (모든 사용자 공유) |
| 스냅샷 | 버전 기록, 되돌리기, 현재와 비교, JSON 내보내기 |
| 연결 | Supabase 연결 |

## 저장

연결 전에는 브라우저의 localStorage 에만 저장됩니다 (`src/storage.js`).
`연결` 탭에서 Supabase 를 붙이면 계정에 저장되어 다른 기기에서도 이어서 볼 수 있습니다.

| 내용 | 테이블 | 공개 범위 |
|---|---|---|
| 수입·지출·큰 지출·시나리오 | `plans` | 본인만 |
| 버전 스냅샷 | `snapshots` | 본인만 |
| 기관 | `orgs` | 모든 사용자 공유 |
| 할부·대출 상품 | `products` | 모든 사용자 공유 |

### Supabase 붙이기

1. [supabase.com](https://supabase.com) 에서 프로젝트 생성
2. SQL Editor 에 `supabase-schema.sql` 을 붙여넣고 실행 (테이블 4개 + RLS 정책)
3. Project Settings → API 에서 **Project URL** 과 **anon public key** 복사
4. 앱의 `연결` 탭에 붙여넣고 저장 → 이메일·비밀번호로 가입 또는 로그인

> anon key 는 공개용 키라 브라우저에 두어도 됩니다. 실제 접근 제어는 2단계에서
> 만든 RLS 정책이 담당합니다. **service_role 키는 절대 넣지 마세요** —
> RLS 를 우회해서 다른 사용자의 데이터까지 열립니다.

연결한 뒤에도 모든 변경은 localStorage 에 함께 저장됩니다. 서버 저장이 실패해도
작업 내용은 남고, 화면 오른쪽 위에 어디에 저장됐는지 표시됩니다.

## 계산

- **원리금균등**: `pmt = P·r / (1 − (1+r)^−n)`, `r = 연이자율/12`
- **원금균등**: 매월 원금 `P/n` + 잔액 이자
- **만기일시**: 매월 이자만, 만기에 원금 일시 상환
- 무이자 개월 수 이내면 이자율 0 으로 자동 적용
- 반복 항목의 연 증가율은 시작월로부터 경과한 해 수만큼 복리 적용
- 예측 기간을 넘어가는 상환액은 `기간 이후 남은 상환` 으로 따로 집계

## 구조

```
index.html
src/
  main.jsx        진입점
  App.jsx         앱 전체 (계산 엔진 + 화면)
  storage.js      localStorage 어댑터
supabase-schema.sql
```

`App.jsx` 안에서 Supabase 는 SDK 없이 REST(PostgREST + GoTrue)를 직접 호출합니다.
의존성을 줄이려는 선택이며, `@supabase/supabase-js` 로 바꾸려면 `sbFetch`,
`sbSignIn`, `sbSignUp`, `remoteLoad`, `remoteSavePlan`, `remoteSyncSnaps`,
`remoteSaveCatalog` 일곱 함수만 교체하면 됩니다.

## 알아둘 점

- 상품 카탈로그의 예시 항목은 금리가 모두 0 인 빈 템플릿입니다. 실제 금리·무이자
  조건은 시점과 조건마다 달라서 채워두지 않았습니다. 견적서나 카드사 공지를 보고
  직접 입력하세요.
- 현재 정책은 로그인한 사용자면 누구나 공용 상품을 등록·수정할 수 있는 위키 방식입니다.
  관리자만 수정하게 조이는 SQL 은 `supabase-schema.sql` 하단에 주석으로 있습니다.
